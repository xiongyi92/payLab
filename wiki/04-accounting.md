# 复式记账与账务体系

PayLab 的账务分两层：

1. **平台账**（`ops.js`）：支付机构自己的四科目，记录应收、应付与手续费；
2. **跨机构账**（`interbank.js`）：网联、银联、CIPS、央行、商业银行等机构的分录，逐环节完成资金清算。

两层都遵循同一条硬约束：**借方合计 = 贷方合计**。

## 1. 平台四科目

| 科目 | 类型 | 正常余额方向 | 含义 |
| --- | --- | --- | --- |
| `CHANNEL_RECEIVABLE` 渠道应收款 | 资产 | 借方 | 渠道尚未结算给平台的资金 |
| `MERCHANT_PAYABLE` 商户待结算款 | 负债 | 贷方 | 平台应付给商户的净额 |
| `FEE_INCOME` 手续费收入 | 收入 | 贷方 | 平台收取的交易手续费 |
| `BANK` 银行存款 | 资产 | 借方 | 实际结算出款的银行账户 |

余额计算：

```text
资产类余额 = 借方累计 − 贷方累计
负债/收入类余额 = 贷方累计 − 借方累计
```

## 2. 支付入账

### 分录

```text
借：渠道应收款        ¥交易金额
  贷：商户待结算款    ¥(交易金额 − 手续费)
  贷：手续费收入      ¥手续费
```

### 示例：支付宝 128.00 元，费率 0.60%

手续费 = `round(12800 × 0.006) = 77` 分 = ¥0.77

```text
借：渠道应收款        128.00
  贷：商户待结算款    127.23
  贷：手续费收入        0.77
```

对应数据结构：

```json
{
  "id": "LG...",
  "bizType": "PAYMENT",
  "bizId": "PAY...",
  "paymentId": "PAY...",
  "amount": 12800,
  "fee": 77,
  "settleDate": "2026-11-02",
  "entries": [
    { "account": "CHANNEL_RECEIVABLE", "debit": 12800, "credit": 0 },
    { "account": "MERCHANT_PAYABLE",  "debit": 0, "credit": 12723 },
    { "account": "FEE_INCOME",        "debit": 0, "credit": 77 }
  ]
}
```

### 教学要点

- 平台并没有「收到钱」，而是形成对渠道的应收款；
- 商户的钱是平台的负债，不是平台收入；
- 手续费在支付成功时确认收入，而不是结算时。

## 3. 退款与冲销

### 普通退款（手续费不退）

```text
借：商户待结算款      退款金额
  贷：渠道应收款      退款金额
```

### 补偿退款（手续费一并回退）

用于「关单后迟到回调」等场景：

```text
借：商户待结算款      退款金额
  贷：渠道应收款      退款金额

借：手续费收入        原手续费
  贷：商户待结算款    原手续费
```

若支付已结算，退款冲减商户待结算款，可能形成负数，从商户后续结算款中扣回。

### 示例：支付 999.00，退款 30.00

```text
借：商户待结算款       30.00
  贷：渠道应收款       30.00
```

手续费不退还，因此商户最终净额 = 支付净额 − 退款金额。

## 4. 结算出款

结算批次按商户聚合：

```text
净额 = 交易总额 − 手续费总额 − 退款总额
```

### 净额为正

```text
借：商户待结算款      净额
  贷：银行存款        净额
```

### 净额为负（退款多于收款）

```text
借：银行存款          |净额|
  贷：商户待结算款    |净额|
```

结算成功后：

- 批次状态 `PENDING → SETTLED`；
- 批次内支付单写入 `settledBatchId`；
- 生成一条 `bizType = "SETTLEMENT"` 的分录。

## 5. 幂等与防重复记账

所有平台分录写入前都会检查：

```js
ledgerExists(bizType, bizId)
```

| 业务 | bizType | bizId |
| --- | --- | --- |
| 支付入账 | `PAYMENT` | 支付单 ID |
| 退款冲销 | `REFUND` | 退款单 ID |
| 结算出款 | `SETTLEMENT` | 结算批次 ID |

同一业务重复触发时，返回已有分录，不再新增。

## 6. 跨境支付的账务口径

跨境支付以人民币入账：

- 原币金额（USD）只用于结汇折算与报文展示；
- 平台分录使用结汇后的人民币金额；
- 手续费 2.80% 中含 CIPS 网络清算成本，平台账只记录总收入；
- 成本拆分发生在跨机构链路中（CIPS 网络费 + 平台收入）。

示例：724.00 元（USD 100.00 × 7.24），手续费 20.27：

```text
借：渠道应收款        724.00
  贷：商户待结算款    703.73
  贷：手续费收入       20.27
```

详见 [跨境支付专题](06-cross-border.md)。

## 7. 试算平衡

### 平台账

结算页展示四个科目的借贷累计与余额。健康状态应满足：

```text
Σ 借方发生额 = Σ 贷方发生额
```

### 跨机构账

清算链路每完成一个环节就写入一组分录，`postJournal` 在写入时校验：

```js
const debit = lines.reduce((sum, line) => sum + line.debit, 0);
const credit = lines.reduce((sum, line) => sum + line.credit, 0);
if (debit !== credit) throw new Error('借贷不平衡');
```

全局试算接口 `GET /api/clearing` 返回：

```json
{
  "trial": { "debit": 862503, "credit": 862503, "balanced": true }
}
```

## 8. 会计计算展示

「阶段详情」中的会计计算分三类：

| `accounting.kind` | 出现阶段 | 内容 |
| --- | --- | --- |
| `ENTRY` | 账务入账 | 完整分录、借贷合计、平衡校验、凭证号 |
| `FLOW` | 交易完成 | 跨机构链路进度、净额、网络费、平台费 |
| `NONE` | 其余阶段 | 金额口径与计费公式，说明本阶段为什么不记账 |

每个阶段都会展示基础公式：

```text
交易金额 = ¥...
手续费 = 交易金额 × 费率 = ¥...
商户净额 = 交易金额 − 手续费 = ¥...
```

跨境阶段额外展示：

```text
原币金额 = USD 100.00
结汇人民币 = 10000 × 7.24 = ¥724.00
```

## 9. 相关 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/payments/:id/accounting` | 单笔交易的完整会计链路 |
| `GET` | `/api/settlements` | 平台科目汇总、结算批次 |
| `GET` | `/api/clearing` | 机构余额与全局试算平衡 |
